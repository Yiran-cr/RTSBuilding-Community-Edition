客户端输入 → C2S 发包 → 服务端分发 → Pipeline 业务处理 → S2C 反馈的完整闭环。

2.3 关键机制

协议安全护栏：ActionType 按 ordinal 编解码，删除枚举值会使后续序号前移导致新旧端协议错位——故已移除的 action 以 @Deprecated 占位保留。
C2S 收口：客户端全部经 RtsClientPacketGateway；服务端全部经 ServerActionHandler。

3走查发现的问题与修复

3.1 边界问题（B，8 项已修复）

B1 · C2S 解码 ordinal 越界可抛 AIOOBE 已修复

根因：ActionType.values()[buf.readVarInt()] 无下标保护，恶意包携带超大 ordinal 在 decode 阶段抛 ArrayIndexOutOfBoundsException，且不在 handler try-catch 保护内。
修复：decode 校验 0 <= ordinal < values().length，非法值返回 null 丢弃包。

B3 · face（方向）越界未 clamp 已修复

根因：Direction.from3DDataValue(t.getByte("face")) 直接使用客户端字节，MC 内部 BY_3D_DATA[index & 3] 对部分越界值错位映射。
修复：新增 safeFace(t) 校验 0..5，越界回退 DOWN，替换 6 处调用。

B4 · INTERACT_BLOCK 无模式守卫 已修复

根因：其它动作均有 isBuildMode / isInteractOrBlueprintMode 守卫，唯独 INTERACT_BLOCK 无任何模式/相机校验。
修复：增加 RtsCameraManager.isActive(p) 守卫，与服务层校验一致。

B5/B6 · 相机姿态坐标无校验（可污染/失控） 已修复

根因：updateCameraPose 对客户端上报坐标/角度无数值校验，恶意坐标可 spawn 无人机到任意位置、heightOffset 可成 NaN。
修复：入口防御——非有限坐标回退锚点，x/z 按半径 clamp，y 按高度 clamp，yaw wrap，pitch clamp。

B8 · areaMine 范围反向空扫 已修复

根因：clamp 只压缩 max，若客户端传入 min > max 则范围反向，扫描空遍历。
修复：每个维度先做 min/max 规范化再 clamp。

B14 · FUNNEL_BOX_PICKUP 实体列表无上限 已修复

根因：sendFunnelBoxPickup 对实体 ID 列表无大小限制。
修复：客户端发送前截断至 ≤256。

B16 · requestPage 重载参数覆盖拼音设置 已修复

根因：交互刷新页面用 7 参重载硬编码 pinyinSearchEnabled=false，覆盖会话设置。
修复：改用 6 参重载自动继承会话设置。

3.2 断点问题（D，6 项已修复）

D1 · S2CRtsRemoteMenuHintPayload 单向断头 已修复

根因：payload 已注册、服务端正常发送，但 dispatchStorage switch 无对应 case 落入 default 静默丢弃。
修复：删除冗余自定义 payload，保留原版方块刷新逻辑。

D2 · handleBlueprintStatus 空实现 已修复

根因：handleBlueprintStatus 方法体为空，服务端正常发送状态包。
修复：实现翻译 + 按状态加颜色前缀（§a 成功 / §c 错误 / §7 普通）通过 displayClientMessage 反馈。

D3 · CAMERA_POSE 动作分支永不命中 已修复

根因：服务端保留 case CAMERA_POSE，但相机姿态走专用 C2SCameraPosePayload，无代码构造该 C2SAction。
修复：删除该 case；枚举值保留（防 ordinal 前移）。

D4 · RtsPathfindingPackets 空壳注册 已修复

根因：register() 方法体为空却被调用，路径查找实际走 C2SAction.PATHFIND。
修复：删除该文件并移除调用。

D5/D9 · 工作流超时服务从未启动（僵尸工作流） 已修复（按决策删除）

根因：startTimeoutService 已实现但全仓库无调用者，僵尸工作流永不清理，槽位耗尽后新请求被拒。
修复：整体删除超时服务、引擎 start/stop 方法、事件总线 fireEvent 空实现及 WorkflowEvent 残留。

D11 · 切维度时 tickable 管道悬挂 已修复

根因：TickablePipelineRegistry.removeAll 仅登出时调用，切维度时旧维度管道不清理。
修复：onPlayerChangedDimension 追加 removeAll(player.getUUID())。

4边界与设计说明

  • C2S 收口：客户端全部经 RtsClientPacketGateway；服务端全部经 ServerActionHandler，禁止旁路。
  • S2C 收口：全部经 ClientPayloadDispatcher 按域 switch，服务端不直接引用客户端类。
  • 协议安全：ActionType 按 ordinal 编解码，删除枚举值会导致新旧端错位——故占位保留而非删除。
  • 建议后续：B12 可做延迟落盘优化；R3 挖掘校验可收敛到 RtsMiningValidator 谓词中心；相机高频通道可加最小间隔节流。
