3走查发现的问题与修复

3.1 边界问题（B，8 项已修复）

B1 · 预览过滤条件与服务端不一致 已修复

根因：预览仅做"同类型 + destroySpeed≥0"，服务端额外要求硬度比 ≤1.5x 和动作半径校验。
修复：预览过滤器补充硬度比与动作半径过滤，使高亮与实际连锁范围一致。

B2 · ultimineProgressPos 从不随目标推进更新 已修复

根因：批处理循环只 removeFirst 逐个破坏，从不更新 progressPos，裂纹始终钉在首个目标。
修复：每次取出目标后立即更新 progressPos，使裂纹动画跟随推进。

B3 · 校验失败目标仍占用 processed 计数 已修复

根因：循环顶部无条件 processed++，即使随后 continue 跳过。
修复：校验通过（真正尝试破坏）后才 processed++，抽为 isTargetMineable。

B4 · 预览不含工具 / 半径预检 已修复

根因：预览 BFS 不含动作半径校验，超半径种子服务端静默返回空。
修复：预览过滤增加相机锚点 X/Z 半边长（maxRadius）判定。

B5 · 首目标破坏失败 → 丢弃整个批次 已修复

根因：单块完成路径 if (result.broken() && !ultimineTargets.isEmpty())，首目标失败落入单方块分支直接 finalize。
修复：改为 if (!ultimineTargets.isEmpty()) 无论成败都 removeUltimineTarget 并继续批次。

B6 · 单块 / 批处理两种计数方式不一致 已修复

根因：首目标单块路径用 Math.max(processed,1)，批处理用 processed++。
修复：统一为"已尝试处理即 processed++"。

B7 · ultimine mode 硬编码 0 已修复

根因：客户端发送 (byte) 0 的 mode，预览固定按同类型过滤。
修复：抽取 ULTIMINE_MODE = 0 常量，为后续 mode 扩展留统一入口。

B8 · isBuildMode 在相机未激活时直接放行 已修复

根因：原实现 if (!isActive(p)) return true，相机未激活反而放行。
修复：收紧为相机未激活 return false，并要求会话模式为 BUILD。

3.2 断点问题（D，4 项已修复）

D1 · 破坏动画处理器为空实现 已修复

根因：handleBreakAnimation 空方法，每块发包全浪费。
修复：实现处理器——清除残留裂纹并触发破坏粒子（后续演进为客户端本地播放破坏音）。

D2 · ultimine 进度链路无消费 已修复

根因：服务端仅在中止时发 (-1,0)，客户端写入后无渲染消费。
修复：改为批次完成信号——finishUltimineBatch 结束发送 (-1,0)，客户端清除 activePos，删除无消费字段与 getter。

D3 · 连锁批次无取消入口 已修复

根因：批次点击即发、无取消；服务端 mine(start=false) 对已提交批次拒绝停止。
修复：① 客户端批次进行中（activePos!=null）再次左键 = 取消；② 服务端对任一活跃挖掘均执行 STOP_MINING。

D4 · 预览高亮但服务端静默拒绝 已修复

根因：种子不可挖时 collectUltimineTargets 静默返回空。
修复：预览侧先做半径约束过滤（B4），让不可达目标不出现在高亮中。

4边界与设计说明

  • 预览与实际一致性：预览过滤（硬度比 ≤1.5x + 动作半径）与服务端 isUltimineCandidate 对齐，避免"高亮但挖不到"。
  • 批次取消：activePos 非空时再次左键 = 取消，服务端对任一活跃挖掘均支持 STOP_MINING。
  • 完成信号：批次结束必发 (-1,0)，保证客户端 activePos 被清除（否则下一次点击被误判为取消，需点两次）。
  • 已知近似：预览无法精确模拟服务端 MiningSpeedCalculator 的完整工具速度判定（借用工具/附魔/药水/水下惩罚），"无合适工具时点击无反应"仍可能发生——玩家可见手上物品，属可接受近似。
  • 建议后续：若需完全对齐工具速度，可考虑服务端下发最近一次 ULTIMINE 收集结果给客户端复用。
