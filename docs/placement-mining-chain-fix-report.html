3走查发现的问题与修复

3.1 边界问题（B，5 项已修复）

B1 · 破坏作业挂起时 token 为 null 导致 NPE 已修复

根因：RtsBatchJobTickOps.checkPausedOrCancelled 对 workflowEntryId=-1 返回 WorkflowTokenHolder(null)，tickDestroyJobs 直接 .get().suspend() 抛 NoSuchElementException。
修复：两处改用 tokenOpt.ifPresent(...)，null token 安全跳过。

B2 · 区域挖掘坐标 clamp 整数溢出 已修复

根因：clampedMinX + AREA_MINE_MAX_SIZE - 1 用 int 运算，min 逼近 Integer.MAX_VALUE 时溢出为负。
修复：新增 clampMaxAxis 用 long 中间量计算并 clamp 到 Integer.MAX_VALUE。

B3 · 放置打开远程菜单后缺少终止分支 已修复

根因：placeWithStorageItem 检测到菜单变化后调 markRemoteMenuOpen 但没 return，继续执行 fallback 放置；且已从 carried 扣减物品。
修复：打开菜单分支补 return false，并先将 carried 扣减物归还再同步权威状态。

B4 · 工具原型断链：isSelectedMiningToolRequested 恒为 false 已修复

根因：网络入口对 MINE/ULTIMINE/AREA 硬编码 toolPrototype=EMPTY，而该判断要求原型非空 → 恒 false，工具借用退化为使用主手。
修复：支持空原型，按 toolItemId 解析物品并以"不可堆叠=工具"启发式判断；borrowMiningTool 按 itemId 构造最小原型。

B5 · 命中偏移 hitOffset 未归一化 已修复

根因：hitOffset = hitX - clickedPos.getX() 直接使用客户端上报 double，有限值任意大小都放行。
修复：sanitizeHitOffset 有限值 clamp 到 [0,1]，非有限值回退基于面的默认偏移。

3.2 断点问题（C，4 项已修复 · 1 项保留）

C1 · QUICK_BUILD 形状放置客户端无入口 + 死 UI 状态 已修复

根因：BuildingModule.placeSelected 恒传 quickBuild=false，且 quickBuildOpen 三件套与 buildShapeOrdinal 无调用方。
修复：删除死 UI 状态；保留服务端 QUICK_BUILD 能力供 API 使用。

C2 · AreaOperationExecutor 放置侧方法全部无调用方 已修复

根因：generatePositions 等 5 个方法全仓库无调用，与 RtsPlacementQuickBuild 形成两套并存实现。
修复：删除 5 个死方法，保留 scanAreaMineTargets 与 filterBreakableTargets。

C3 · StatePlacementPlan.selectedStorageItem 死字段 已修复

根因：record 组件从未被读取，Javadoc 声称"false=使用主手堆叠"与实际"恒从储存提取"不符。
修复：删除该组件及构造参数。

C4 · allowPlacedBlockRecovery 网络链路恒 false 保留（合理）

取回功能由独立 BREAK 动作（RtsPlacedRecoveryService.breakPlaced）承担，属产品行为；服务端恢复分支保留给 API 调用方。

C5 · startUltimine 未设置 toolPrototype 已修复

根因：与 mine/areaMine 不同，startUltimine 构建 MiningContext 时未调 .toolPrototype(...)。
修复：随 B4 一并修复——ToolBorrowPipe / borrowMiningTool 空原型时按 toolItemId 解析。

3.3 无效代码（D，5 项已修复 · 1 项保留）

D1 · 静态 RtsPlacementService 整个类无调用方 已修复

方法体内从不读取 quickBuild（快速建造走独立路径）。删除参数并同步更新 RtsPlacementBatch 调用点。

D5 · TopBarPanel 空方法与死字段 已修复

仅转发 Cached 版且参数顺序不同，极易误用。删除转发方法，调用点改走 Cached 版。

E5 · 两套形状放置实现并存 保留（架构）

AreaShapeGenerator 体系（放置侧无人接线）与 RtsPlacementQuickBuild（实际使用）功能重叠。统一属架构级重构、风险高，留作后续独立任务。

4边界与设计说明

  • 工具借用语义：空原型时按 itemId + "不可堆叠=工具"启发式判定，避免把红石/种子误判为工具。
  • 命中偏移归一化：客户端 hitOffset clamp 到 [0,1]，非有限值按面回退，纵深防御。
  • 快速建造 vs 交互式放置：形状放置走快速路径（精确 setBlock），单点/交互走 useItemOn（按面偏移），两套语义需注意边界。
  • 协议 ordinal 护栏：已移除 action 用 @Deprecated 占位而非删除，防新旧端错位。
  • 建议后续：统一 AreaShapeGenerator 与 RtsPlacementQuickBuild 两套形状放置实现（架构重构，单独评估）。
