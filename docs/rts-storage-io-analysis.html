2.3 关键机制

背包与存储条目合并：同一物品（含组件相同）只保留一条，数量 = 存储 + 背包加总；点击拿起从网络（存储优先、背包兜底）提取。
carried 权威回写：carried 一律以服务端 S2CRtsCarriedSyncPayload 权威状态为准，不做乐观 setCarried。

3走查发现的问题与修复

3.1 边界问题（B，8 项已修复）

B1 · 放回储存的携带数量固定为 64 已修复

根因：客户端调用 sendReturnCarried(itemId, 64) 固定传 64，大堆叠 mod 时只存回 64 个，剩余滞留 carried。
修复：三处改为传实际数量 carried.getCount()，实现全量存回。

B2 · 点击"存储条目"兜底抽取玩家背包 已修复

根因：点击存储条目存储不足时兜底从玩家主背包抽取，出现"显示数量与动了谁不一致"。
修复：条目合并显示网络总量后，pickup 恢复网络提取（存储优先、背包兜底），显示与操作一致。

B3 · 转移操作缺少 RTS 模式门禁 已修复

根因：LINKED_PICKUP / RETURN_CARRIED / LINKED_QUICK_MOVE / IMPORT_MENU_SLOT 均不校验相机激活。
修复：四个转移 case 统一增加 if (!RtsCameraManager.isActive(p)) return;。

B4 · S2C 页面载荷中 linked 详情列表长度不齐 已修复

根因：编码器用 Math.min 截断 6 个列表，而 linkedPositions 单独按全长写入。
修复：编码器按 linkedPositions.size() 统一等长写入，缺失/越界用默认值补齐。

B5 · 最近条目数量两端不一致 已修复

根因：服务端上限 24、客户端硬编码截 16。
修复：在共享的 S2CRtsStoragePagePayload 定义 RECENT_ENTRY_LIMIT = 24，双端统一引用。

B6 · NBT 变体不匹配时物品丢失风险 已修复

根因：提取是真实执行，归还失败即物品永久丢失。
修复：新增 refundExtractedToSlot，优先插回刚清空的槽位，最终失败随输出返回，保证"数据安全优先于变体纯度"。

B7 · 缓存直接保留 handler 返回的可变栈引用 已修复

根因：对 ReportedCountItemHandler 直接保留 getStackInSlot 返回引用，缓存可被外部污染。
修复：统一 stack.copy() 浅拷贝。

B8 · 每次 REQUEST_PAGE 触发全量构建 + 全量 NBT 写盘 已修复

根因：每次搜索按键 → 全量构建 + 序列化整页 + 全量 session 写盘。
修复：① 客户端搜索 200ms 防抖；② 服务端仅在浏览器状态/页码/最近条目任一变化时才写盘。

3.2 断点问题（C，4 项已修复 · 1 项保留）

C1 · 放回失败时 carried 不同步（原怀疑） 复查确认无需修复

RETURN_CARRIED 在调用后无条件发送 S2CRtsCarriedSyncPayload（即使提前 return 也会回写当前 carried），客户端得以恢复，链路已被"总是同步"逻辑覆盖。

C2 · 乐观 carried 数量与实际提取量脱节 已修复

根因：客户端发送 LINKED_PICKUP 后乐观 setCarried，服务端实际提取量可能更少。
修复：移除乐观 setCarried，carried 一律以服务端权威回写为准。

C3 · "最近使用"条目由双管线维护，删除不生效 已修复

根因：客户端删除最近条目只做本地屏蔽，服务端数据从未删除；客户端启用物品不进入服务端 recent。
修复：打通服务端权威删除链路——枚举追加 REMOVE_RECENT_ENTRY → 网关 → handler → removeRecentItem 真正从会话移除。

C4 · C2SAction 非法 ordinal 解码为 null 触发空指针 已修复

根因：decode 对越界 ordinal 返回 null，handle 直接访问 actionType()。
修复：handle 入口先判空，在任何字段访问前拦截。

C5 · StorageModule.requestPage 断头路径 已修复

客户端实际请求走 StorageState.requestStoragePage，StorageModule.requestPage(int) 无人调用。删除该方法。
