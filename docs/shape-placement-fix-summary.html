2形状放置链路

修复后形状放置统一走快速建造路径（预解析状态计划 + 直接 setBlock），而非修复前错误命中的交互式放置路径（按命中面 face 放置，导致整体偏移一格）。

2.1 触发路径

客户端 — BuilderScreen 事件 → BuildInteractionHandler（tryStartLineBrush 点选）
▼
客户端 — confirmLinePlace → LineBrushSelector.computePositions()（形状几何）
▼
客户端 — RtsClientPacketGateway.sendLinePlace → C2SAction(PLACE_BATCH) + quickBuild=true
▼
服务端 — ServerActionHandler → RtsPlacementServiceImpl.enqueuePlaceBatch
▼
服务端 — Pipeline → RtsPlacementBatch 排队 → 每 tick 节流执行
▼
服务端 — 快速建造 RtsPlacementQuickBuild.placeStateBatchEntry（精确 setBlock）
▼
客户端 — S2CRtsPlaceAnimationPayload → handlePlaceAnimation → grow-in 动画

2.2 关键机制

快速建造 vs 交互式放置：快速路径 quickBuild=true 预解析状态计划后直接 setBlock 到目标坐标，位置精确；交互式路径按 face=UP + hitOffset 构造 BlockPlaceContext，会偏移到目标上方一格。
形状几何上限：各 compute 方法生成时达 MAX_POSITIONS 即停，并用 LinkedHashSet 去重，避免上百万 BlockPos。

3走查发现的问题与修复

3.1 链路断点（3 项已修复）

① 形状建造未走快速建造路径，交互式路径偏移一格 已修复

根因：客户端 sendLinePlace 未发送 quickBuild 字段，服务端 enqueuePlaceBatch 硬编码 .quickBuild(false)，形状放置实际走了交互式路径，BlockItem 放置位置 = clickedPos.relative(UP) 偏移一格。
修复：客户端发送 quickBuild=true，服务端透传并新增 quickBuild 参数，形状放置改走快速建造路径精确放置。

② 无会话 fallback 分支是死代码 已修复

根因：无会话 fallback 调 enqueuePlaceBatch(player, null, ...)，该方法首行 if (session == null) return false，fallback 永远无效，且 quickBuild 语义矛盾。
修复：删除死代码 fallback，无会话/空位置时直接返回。

③ 快速建造计划解析失败后永久卡死 已修复

根因：statePlacementPlan 缓存解析失败（itemId 无效/非方块/chunk 未加载）的结果，解析失败也置 statePlanResolved=true，后续 tick 永不重试。
修复：解析失败不缓存，后续 tick 重新尝试；计划为 null 时跳过该位置，不再回退到交互式路径。

3.2 边界问题（3 项已修复）

④ 超大形状生成上百万 BlockPos 再截断 已修复

根因：MAX_RADIUS=64 时球 ≈ 109 万格、体 = 262144 格，远超 MAX_POSITIONS=32768，先生成全部位置再截断浪费内存且取 DDA 顺序前 N 个（球只放底部一片）。
修复：BuildShape 各 compute 生成时达上限即停，LinkedHashSet 去重，超限提示改为"达到上限已截断"。

⑤ 球形状在 hover 为空时无预览 已修复

根因：shouldRender 要求 getHover()!=null，但球（SPHERE）几何只依赖球心+半径，鼠标移出世界区时预览消失。
修复：shouldRender 对球形状放宽 hover 非空要求。

⑥ 声音限流注释与常量不一致 已修复

MAX_SOUNDS_PER_TICK=1 但 javadoc 写"最多 2 次"。注释改为引用常量。

3.3 无效冗余代码（3 项已清理）

⑦ ShapeButtonGroup 六个未使用方法 已清理

isLine/isWall/isPlane/isSolid/isCircle/isSphereConstructionSelected 全代码库无调用（统一走 getBuildShape() 的 switch），已删除。

⑧ BuildInteractionHandler 无用字段 已清理

miningMouseButton 只被赋值从未读取，已删除。

⑨ sendLinePlace / sendAreaBoxPlace 重复代码 已清理

约 20 行重复的 tag 构建提取为公共 sendBatchTag，避免漏改副本产生断点。

3.4 不修复导致的后果汇总

问题若不修复的后果
断点 1：形状走交互式路径放置位置整体偏移一格，形状与预览错位；大形状建造卡顿；快速建造优化永不生效。
断点 2：死代码 fallback无会话时兜底从未执行，两条路径 quickBuild 语义矛盾。
断点 3：计划解析失败卡死chunk 未加载即整批永久失败；且静默回退交互式路径再次触发偏移。
边界 4：超大形状大球/大体块建造瞬间内存峰值高、卡顿；球体只生成底部一小片，形状残缺。
边界 5：球预览消失鼠标移出世界区时球线框不可见，无法精确确定球心/半径。
冗余 6-9：无效/重复代码维护成本累积，新增功能时极易漏改副本导致隐性 Bug。

4边界与设计说明

  • 快速建造统一：形状放置统一走快速路径（位置精确、性能稳定），与客户端预览完全一致。
  • 形状上限保护：几何生成达 MAX_POSITIONS 即停 + 去重，防止客户端内存/卡顿。
  • 球预览放宽：球几何不依赖 hover，仅需球心 + 半径。
  • 核心结论：最严重的是断点 1——它同时造成"位置偏移"和"快速建造优化失效"，是所有形状放置问题的根因。
